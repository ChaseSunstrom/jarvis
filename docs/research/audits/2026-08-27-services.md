## Defects, ranked

1. **The orchestrator has no model.** Root compose passes `OLLAMA_URL=${OLLAMA_URL:-http://127.0.0.1:11434}` and never `LLM_URL`; `app/main.py::_model_base_url` reads `LLM_URL` first, so the container falls back to `http://127.0.0.1:11434/v1`, where nothing listens on this host. `.env` sets `LLM_URL=http://127.0.0.1:4000/v1` (the gateway, which serves `house` and `house-fast`), and `jarvis-core/.env` sets `PLANNER_MODEL=CODER_MODEL=qwen3.8-27b` — but the root compose reads the root `.env`, which has neither, so the orchestrator asks for `qwen3:8b` / `qwen2.5-coder:7b`. `/delegate` therefore fails every task in 25 ms; `docs/LIVE_TEST_REPORT.md:68` shows the consequence (`delegation-across-backends … routed to 'research', expected 'subagents'`). No test pins the orchestrator's env the way `test_packaging` pins jarvis-core's (`test…never passes them into jarvis-core` covers only the core service), and no gate calls `/delegate` live (`m42-delegation.sh` scores tool names; `m82` only posts `/code_task`). Files: `docker-compose.yml:167-175`, `jarvis-orchestrator/app/main.py:26-38`, `jarvis-orchestrator/app/fanout.py`.
2. **BLOCKERS "Debian mirror" is still true, and the fix is two steps, not one.** The running image (built 26 Aug 23:58:50, after the M82 Dockerfile change 7ad4019) has no `git`, `curl`, `unzip` or `opencode` (`rc=127`). `jarvis-workspace/.code_jobs/5629026e3355.json` (the operator's React app) is `error: opencode binary not installed in orchestrator image`; the three `m82-probe` records are `no such workspace repo` — the gate's probe. 3. **`scripts/egress-audit.sh` returns FAIL on a healthy, isolated sandbox** because `ls /sys/class/net` lists `bonding_masters` (a file, not a link). Every reachability probe passed. `THREAT_MODEL.md` cites this script as the assertion for two of its five rules and for "nothing is on the public internet" — it asserts neither inbound exposure nor anything beyond the sandbox's egress, and its verdict is currently wrong. ## Resilience (what jarvis-core does when a service is down) — code matches docs

- **web** (`integrations/web/client.py`): SearXNG down → `SearchFailed("SearXNG is unreachable at <base> …")`; browser down → `BrowserFailed("jarvis-browser is unreachable at <url> …")`; unconfigured → `SearchNotConfigured` / `BrowserNotConfigured` with the setting to fix; tools return `{"status":"error","error":…}`. No cloud fallback anywhere (the one fallback is another SearXNG, `docs/search.md`). Live: `web ready: searxng=https://searxng.tail05d9af.ts.net browser=http://127.0.0.1:8210 act_allowlist=0`.
- **research** (`integrations/research/__init__.py:43,315`): refuses with "no model configured" or the web error; a worker exception never takes the loop down; report/note write failures are warnings.
- **orchestrator** (`integrations/orchestrator/__init__.py:268-306`): unconfigured → `NotConfigured` with an explanation, and a startup WARNING; unreachable → `OrchestratorError("could not reach the orchestrator at <url>: …")`; ≥400 → the service's `detail`; equal secrets → startup ERROR. **Gap:** startup says `orchestrator ready: configured=True can_approve=True` while the service's own model is unreachable — `/healthz` reports `{"status":"ok"}` and nothing else, unlike the browser's, which reports its backend and config. The card will fail; nothing on the Settings screen says why (memory: *operator looks in Settings*).
- **code** (`integrations/code/sandbox.py:783`): `_explain_docker_failure` names "docker is not installed", socket permission, daemon down, image pull; the remote job's watcher reads the orchestrator's own error within a poll (M82, `test_orchestrator.py` (50)).
- **browser service itself**: refuses to start without both secrets; a missing chromium is a 502 with a message, not a 200 (Dockerfile probes the launch at build).
