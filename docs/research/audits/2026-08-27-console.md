## 2. Defects, ranked

1. **Approvals banner never seeds from the real server.** `jarvis-web/src/lib/jarvisClient.ts:925-933` — `pendingApprovals()` calls `call_service llm.pending_requests` and reads `result.response ?? result.result ?? result.requests`, keeping it only if it is an array. The server answers `{"context":…, "response": {"pending": [...]}, "changed_states": []}` (`jarvis-core/jarvis/integrations/llm/__init__.py` `handle_pending` → `{"pending": registry.pending_requests()}`; verified live: `response.pending[0].tool == "change_setting"`). `response` is an object, so the console gets `[]`. The mock answers `{ response: world.approvals }` — a bare array — at `tests/web/mock-ha.mjs:2416`, which is why `approvals.spec.ts` passes. Effect: open or reload the console after a voice turn raised a Tier-3 request and the banner is empty until the next `jarvis_approval_required`; the live house has such a request pending right now.
2. **Settings › Tools says n8n is connected when it is not.** `jarvis-web/src/lib/components/N8nConnection.svelte:31-33` unwraps `result.service_response ?? result`. The server keys a service response `response` (`websocket.py:663`, `common.py:277-281`), so `status` becomes the whole envelope, `status.status` is `undefined`, and the template falls through to the `{:else}` branch at :61-63: `connected · undefined · 0 workflows, 0 active`. Live `n8n.status` answers `response.status = "not_configured"`. The mock's `n8n.status` is the one place in the file that uses `service_response` (`mock-ha.mjs:2407`; 25 other answers use `response:`), so `n8n.spec.ts` passes against a shape the server never sends.
3. **`jarvis_setting_changed` is fired and nobody listens.** `settingsStore.svelte.ts`, `SettingControl.svelte`, `Models.svelte`, `sectionLink.svelte.ts` have no subscription. After M67 (voice `change_setting`) and M80 (`demo.enabled`), a Settings section that is open keeps the old value and the old MODELS role until reload.
4. **Areas is not live.** `sections/Areas.svelte` makes no `subscribeEvents` call; `entity_registry_updated`, `area_registry_updated`, `device_registry_updated` are ignored. M69's removals and any assignment made on Devices or by voice leave the page stale. `editable-house.spec.ts` proves live removal on Devices and Dashboards only.
5. **ScheduledJobs is not live.** No subscription; `jarvis_schedule_fired` unused, so `next_at`, `last_result` and `missed` move only on reload (`schedule.spec.ts` "a firing that was missed is surfaced" passes by reloading).
6. **No RETRY.** Server: `jarvis/tasks/retry` (`websocket.py:1410`). Console: no client method, no control on `TaskCard.svelte` or `routes/work/tasks/[id]/+page.svelte`. Live: 10 of 24 tasks are `error`, six of them "interrupted when Jarvis restarted" — the exact case a retry is for.
7. **Mock ↔ server payload drift.** Keys the server sends that the mock never carries: `last_used_at` (token rows; the console declares it in `AccessToken` and shows nothing), `permission_mode` (repositories), `expires` (memory entries). Routes the console calls that the mock does not serve: `POST /api/voice/speaker/enrolling` (`EnrolVoice.svelte:136`; the M79 "not listening while you enrol" signal is therefore never exercised by e2e). And the two shape divergences in defects 1–2. Nothing the console reads today is *missing* from the mock; the drift is one interface field away from the failure CLAUDE.md names.
8. **Sent, never shown.** `AccessToken.created_at`/`last_used_at` (`Pairing.svelte` renders id, name, connected); `AutomationRow.reach` (`common.py:1271`); repo `backend`/`permission_mode`/`origin`/`environment_detail`/`managed` (`code/workspace.py:198-201`); `MemoryEntry.expires`; `surface.max`. Each is small; together they are what "operator looks in Settings" counts as missing.
9. **`docs/verification.md:68` is stale**: "`jarvis-web` (Playwright, chromium) | 59". There are 37 spec files with 233 `test()` calls plus five per-screen loops (`controls`, `look`, `responsive`, `states`, `menus` over ~19 screens). Line 66 "vitest, 24 files" — `find src -name '*.test.ts'` counts 43. Re-measure with the command on line 50; do not edit the numbers by hand.
10. **Plan overpromise (M82).** `docs/OVERHAUL_PLAN.md:104` — "the worker's state on the Code screen". `sections/Code.svelte` has no worker/orchestrator readout; the gate checks the watcher, the Dockerfile and the orchestrator's HTTP answer only. The live Code listing (`environments: []`, `forges: []`, `sandboxed: false`) gives the screen nothing to say about the worker either.
11. **`+error.svelte:29`** "Back to the console" goes to `/devices`, a 308 away from `/house/devices` since M48. Works; one hop stale.
12. Live data, not console: 66 registry entities, 14 with an `area_id`, 31 with a state; every reading has `area: ""`. The House dashboard's "readings by room" is therefore one group, "elsewhere". Worth a sentence on the widget ("no sensor has a room yet — assign one on Devices") rather than the generic room list.

## 3. Coverage gaps

- **Dedicated specs, by screen**: Voice 7 specs · Dashboards 2 · Devices 4 · Areas **0** (1 test inside `e2e.spec.ts`, 1 in `console-repairs`) · Automations **0** (2 tests inside `e2e.spec.ts`) · Tasks 3 · Task detail 1 · Code 1 · Notes 1 · Memory 1 · Knowledge graph 1 · Assistant 2 · Voice settings 2 · House settings **0** (2 tests inside `settings.spec.ts`) · Console 2 · Tools 6 · Styleguide 1. The five generic loops (`controls`, `look`, `responsive`, `states`, `menus`, plus `ui-review` behind `UI_REVIEW=1`) walk every screen in `screens.ts`.
- **Untested against the server's real shape**: the approvals seed (`llm.pending_requests`) and the n8n line (`n8n.status`) — the mock encodes the console's assumption, not the server's answer. A contract file (`tests/contracts/*.json`, read by `test_api.py` and the mock) is the house pattern for exactly this.
- **Untested because the mock lacks the route**: `POST /api/voice/speaker/enrolling`.
- **No e2e for live refresh** on Areas, Settings (a `jarvis_setting_changed` push), ScheduledJobs (`jarvis_schedule_fired`).
- **No screenshot** in `docs/ui-review/` for the task detail screen (`ui-review.spec.ts:22` skips paths with `[`), so the one C2 "task view" the migration doc names is the one nobody looks at.
- Docs vs tree: `UI_MIGRATION.md` §3 — every box ticked and the tree agrees (SectionStrip, ScreenTitle, TaskDock on Voice, the menu inventory's primaries and search counts). `docs/design/README.md` and `docs/ui-review/README.md` match what exists. `BLOCKERS.md` items are all server-side; nothing on the console promises them.

## 4. Suggested milestones

1. **One shape for a service response** — a `tests/contracts/service_response.json` (`response`, never `service_response`; `pending_requests` → `{pending: []}`) read by `test_api.py` and the mock; fix `pendingApprovals()` and `N8nConnection`; `approvals.spec` reloads with a held action and sees it; `n8n.spec` sees "not configured" on the server's shape.
2. **Settings that follow the house** — subscribe `jarvis_setting_changed` in `settingsStore` and `Models`; a voice `change_setting` in the spec moves the row and the role pill without reload.
3. **Areas and the schedule, live** — Areas on the three registry events; ScheduledJobs on `jarvis_schedule_fired`; `editable-house.spec` gains the Areas case.
4. **Retry from the console** — `retryTask()` over `jarvis/tasks/retry`; RETRY on a failed card and on the task page (one primary, quiet); e2e on a task the mock fails.
5. **Say what the server already says** — token created/last-used on Console rows, `reach` on an automation row, backend/permission mode on a Code repo row, `expires` on a memory row, "no sensor has a room" on Readings.
6. **Mock parity, measured** — a verify script that diffs the keys of every live list payload (via the websocket) against the mock's world and the console's interfaces, so defect 7 cannot recur silently; add `/api/voice/speaker/enrolling` to the mock.
7. **Re-measure the web rows of `verification.md`** with the command on its line 50 (Playwright count, vitest file count) — a `/claims` run, not an edit.
8. **The worker on the Code screen (M82's second clause)** — orchestrator reachability and the binary's presence from `jarvis/code/list`, one line under the repositories; or strike the clause from the plan row.
